# Data dictionary

## Source and provenance

The initial dataset is **reproducible synthetic data generated by this repository**. It does not contain real cardholders, PANs, accounts, merchants, production traffic, or AtlasPay production records. The synthetic model exists to exercise realistic payment-analysis grains and failure modes safely.

## Dimensions

### `dim_currency`
Grain: one row per ISO-style currency code used by the synthetic dataset.

- `currency_code`: analytical currency key.
- `currency_name`: display name.
- `minor_units`: decimal scale used to interpret integer money fields.

### `dim_issuer`
Grain: one row per synthetic issuer route.

- `issuer_id`: stable analytical issuer key.
- `issuer_name`: synthetic display name.
- `country_code`: issuer country segmentation attribute.

## Facts

### `fact_payment`
Grain: one logical payment.

- `payment_id`: stable synthetic payment identifier.
- `created_at`: payment creation timestamp.
- `currency_code`: payment currency.
- `issuer_id`: issuer selected for the payment.
- `amount_minor`: requested payment value in integer minor units.
- `final_status`: `captured`, `declined`, `reversed`, or `timed_out`.

**Important:** payment amount metrics must be calculated from this grain, not from authorization attempts, otherwise retries can double-count volume.

### `fact_authorization`
Grain: one authorization attempt for one payment.

- `authorization_id`: attempt identifier.
- `payment_id`: logical payment.
- `attempt_no`: attempt sequence per payment.
- `requested_at`: attempt timestamp.
- `disposition`: approved, declined, or timed out.
- `response_code`: synthetic issuer response code when available.
- `latency_ms`: measured response latency; null for timed-out attempts by contract.

### `fact_reversal`
Grain: one reversal linked one-to-one to an authorization and payment in the current model.

- `reason`: timeout, late response, or operator-initiated synthetic scenario.

### `fact_reconciliation`
Grain: one daily currency reconciliation control.

- `expected_minor`: warehouse-computed expected captured amount.
- `observed_minor`: synthetic observed control total.
- `discrepancy_minor`: observed minus expected; enforced by a database check constraint.

## Marts

### `mart_payment_daily`
Grain: calendar day × currency.

Decision use: executive payment health, authorization funnel, decline mix, reversal causes, latency, volume, and reconciliation exceptions.

### `mart_issuer_daily`
Grain: calendar day × currency × issuer.

Decision use: compare issuer approval rate, timeout rate, decline composition, reversal behavior, and latency without mixing payment and attempt grains.
