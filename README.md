# AtlasAnalytics

Payments analytics and decision-intelligence portfolio built around the AtlasPay domain.

AtlasAnalytics is designed for Data Analyst, Analytics Engineer, and Data Scientist hiring evidence. It focuses on trustworthy metric definitions, dimensional modeling, advanced SQL, reproducible synthetic data, data-quality checks, Python analysis, and decision-oriented reporting.

## What is implemented

- DuckDB analytical warehouse.
- Reproducible synthetic payment dataset with no PII or production records.
- Currency and issuer dimensions.
- Payment, authorization-attempt, reversal, and reconciliation facts.
- Daily payment mart with authorization funnel, response-code decline taxonomy, requested/captured volume, reversal causes, P50/P95 latency, and reconciliation exceptions.
- Daily issuer mart with approval rate, timeout rate, decline mix, reversal behavior, and latency.
- Database constraints for impossible states and reconciliation identities.
- Tests that prove authorization retries do not duplicate payment amount.
- CI on Python 3.11 and 3.12 with Ruff and pytest.

## Why the grains matter

A payment is not the same thing as an authorization attempt. A single payment may have multiple attempts. AtlasAnalytics calculates monetary volume from `fact_payment` and operational attempt metrics from `fact_authorization`, preventing retry-driven double counting.

## Run locally

```bash
python -m pip install -e '.[dev]'
ruff check .
ruff format --check .
pytest -q
```

The default warehouse is built in memory:

```python
from atlasanalytics import build_warehouse

connection = build_warehouse()
rows = connection.execute(
    "select * from mart_issuer_daily order by metric_date, issuer_id"
).fetchall()
```

## Data truthfulness

The initial dataset is **synthetic and generated by this repository**. It contains no real PANs, cardholders, accounts, merchants, or AtlasPay production transactions. Synthetic discrepancies and failure states exist specifically to test analytical logic and operator reasoning.

See `docs/data_dictionary.md` for grains and metric semantics and `PROJECT_CONTEXT.md` for the current engineering roadmap.
